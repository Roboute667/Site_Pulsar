# RoutingCat on Cloudflare

This site deploys on Cloudflare: Workers, Pages, or a Worker in front of its server. What RoutingCat needs from Cloudflare, and what Cloudflare changes about it; `operate/cloudflare.md` in the docs has each setting:
- **Workers Paid.** On the Free plan, past 100,000 requests a day, Cloudflare stops the Worker until midnight UTC: a Worker in front of the site's files answers 429 on every page it runs first on, and one on a route in front of a server fails or, failing open, serves undecided and unrecorded. Where the Worker runs first on every path, each file request and beacon is a billed request too.
- **Builds prove themselves with the deploy key:** `ROUTINGCAT_DEPLOY_KEY` in the build's variables. The production key, which the site's owner mints in their own terminal with `npx routingcat keys deploy --branch <production branch>`, serves only builds of that branch, as Cloudflare reports it; one preview key, `keys deploy --env preview`, covers every preview branch. From the person's machine, a build run with `ROUTINGCAT_ENV=production` uses their sign-in alone, ignoring a deploy key in the shell, on a site bound to its Cloudflare project, at `init` or by a move with `--host`; one bound to another host is refused before any plan (A39). It registers once they confirm its plan: at a terminal it asks; run by an agent, it stops with exit 3 and the plan's digest (D115), and runs again with `ROUTINGCAT_CONFIRM=<digest>` once the person agrees. Show them the plan as printed, with any warning beside it, such as uncommitted changes or a branch other than the production branch. Without the variable, and with no deploy key or `ROUTINGCAT_BRANCH` in the shell, it writes development values and registers nothing (D46), and a Worker deployed from them decides nothing.
- **The production address** is in the config: `environments`' production hosts in `routingcat.config.json`, `origin` in Nuxt's and Astro's config. `init` takes it from `--origin`, Wrangler's routes and custom domains, or the stack's configuration; where it finds none, as is usual on Pages, it asks at a terminal, or stops with D88, exit 2: run it again with `--origin https://<your domain>`.
- **Never Workers Cache** on the Worker RoutingCat wraps, which would serve one visitor's page to the next (D80), and no Cache Everything with an edge TTL on routed HTML.
- **Early Hints off on routed paths,** where markup variants carry a main image: the Worker leaves the variants' image preload off, `imagePreload: false`, since Early Hints would hint one visitor's image to the next; left out, it is off on Cloudflare too. Once Early Hints is off there, set `imagePreload: true`. A framework's variants are fields, which name no main image, so a Nuxt or Astro Worker names no preload.
- **Rocket Loader** must skip RoutingCat's script, which carries `data-cfasync="false"`, and Zaraz must not inject into it (D113).
- **Visitors' location** comes from Cloudflare itself on Workers and Pages, with no setting to turn on.
- **Plain HTTP stays undecided:** keep "Always Use HTTPS" on.
- **Each version registers** when its isolates serve their first request; one that hasn't after 10 minutes is D83.
